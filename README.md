# 枢元智能体操作系统

> 以智能体调度为第一性职责的专用系统底座。
> 基于 OpenHarmony 部件化架构，面向龙芯 3A6000（loongarch64）交叉编译，通过自定义 SystemAbility（SA）将意图路由、Agent 注册发现、Skill 调度与执行治理植入系统启动链路，而非寄居在应用沙箱内。

## 1. 项目定位

| 项 | 内容 |
| :--- | :--- |
| 项目代号 | 枢元（Shuyuan） |
| 技术基线 | OpenHarmony（标准系统） + 自研系统服务（SA） |
| 目标硬件 | 龙芯 3A6000，CPU 架构 loongarch64 |
| 宿主构建环境 | Ubuntu 22.04 LTS（物理机或 Win11 + WSL2） |
| 核心工程对象 | 一个或多个自定义 SA，与 `samgr`、`installs` 同级，由 `init` 经 `sa_main` 拉起 |
| 第一版边界 | SA 只做路由、注册、编排与治理；推理循环（ReAct 等）由独立的 Agent 运行时进程承载，不在 SA 内实现 |
| 核心定义 | 目标是**可靠地组织智能**，不是让系统自身推理；智能成为底座能力，而非外挂应用（见 `08-设计基线-组织智能.md`） |
| 当前状态 | 阶段一 SA 骨架 + 串通客户端 + 阶段零脚本已落地；阶段二载阳时序骨架（统一启动 cfg、就绪参数契约）已落地，待真实源码树编译验证 |

**不做什么**：第一版不替代 OpenHarmony 原生 `AgentManagerService`（二者并行，原生服务面向通用应用接口，枢元 SA 作为底层专属调度中枢）；不追求完整发行版功能，按阶段三的裁剪清单收敛到最小必要组件集。

## 2. 七层命名体系

| 层级 | 命名 | 工程标识符 | 一句话职责 |
| :--- | :--- | :--- | :--- |
| 底座 / 内核 | 维岳 | `weiyue`（base） | 底座如山，稳固可依：内核、BSP、基础系统服务 |
| 启动阶段 | 载阳 | `zaiyang`（boot） | 系统启动、智能就绪：启动链路、时序绑定、就绪里程碑 |
| 调度中枢 | 灵台 | `lingtai`（nexus） | 观察、规划、编排的智能中枢：意图路由、Agent/Skill 调度 |
| 感知层 | 监观 | `jianguan`（perception） | 系统感知环境与任务状态，向上供给观测数据 |
| 协作机制 | 和鸣 | `heming`（collab） | 多 Agent、多 Skill 协同编排 |
| 任务闭环 | 令终 | `lingzhong`（closure） | 任务善始善终、可收敛，结果回写与状态终结 |
| 治理 / 审批层 | 敬止 | `jingzhi`（governance） | Agent 行为有边界、可审批、可审计，横切所有动作出口 |

> 命名释义与标识符转写规范见 [`01-命名体系.md`](01-命名体系.md)。

## 3. 架构总览

```
┌─────────────────────────────────────────────────────────┐
│  敬止 jingzhi（治理/审批层 · 横切）                     │
│  权限边界 · 动作审批 · 审计日志 · 合规校验                  │
├─────────────────────────────────────────────────────────┤
│  灵台 lingtai（调度中枢）                                  │
│  意图路由 · Agent 注册发现 · 规划编排 · Skill 调度          │
│      ▲                ▲                ▲                  │
│      │ 状态供给        │ 协同请求        │ 闭环回写          │
│  监观 jianguan     和鸣 heming      令终 lingzhong          │
│  环境/任务感知      多 Agent/Skill 协同  任务收敛与终结      │
├─────────────────────────────────────────────────────────┤
│  载阳 zaiyang（启动阶段）：init 拉起 · bootevent 时序 · 就绪 │
├─────────────────────────────────────────────────────────┤
│  维岳 weiyue（底座/内核）：内核 · BSP · samgr · safwk ·    │
│  init · bundle_mgr · hilog · 最小系统服务集                │
└─────────────────────────────────────────────────────────┘
```

- **依赖方向单向**：维岳 → 载阳 → 灵台；监观供数、和鸣编排、令终收敛；敬止横切所有执行出口，不被业务层反向依赖。
- **详细分层职责、边界与数据流**见 [`02-架构分层与职责.md`](02-架构分层与职责.md)。

## 5. 当前基线结论（来自前期可行性评估）

- 架构原理成立：自定义 SA 是 OpenHarmony 体系内实现早启动、高权限全局服务的标准路径，无原理性障碍。
- 头号工程风险是 **SELinux 策略**：自定义域与 SA ID 授权缺失会导致 `init` 拉起阶段静默失败；开发初期建议先 `permissive` 跑通全链路，再补规则切回 `enforcing`。
- 第二风险是 **3A6000 BSP 完整度**：已核实龙架构主线移植提供 `ls3a5000@loongson`（3A5000/3A6000 7A 主板）PC 镜像与 `qemu-loongarch64-linux-min` 最小虚拟机镜像；具体外设驱动完备度需拉取源码后核实（见 `07-阶段一自研手册.md` 第 8 节）。
- 时间预估为工程经验估算（非官方数据），整体落地约 11–16 周，详见路线图文档。
